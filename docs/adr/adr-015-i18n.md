# ADR-015: Internationalisierung mit Fluent

```{adr} i18n mit Fluent, Deutsch als Standard
:id: ADR_015
:status: proposed
:decides: REQ_NFR_002, SPEC_I18N

**Datum:** 2026-10-15
```

## Kontext
UI in Deutsch und Englisch; Pluralformen und Zahlen-/Datumsformate müssen
korrekt sein.

## Entscheidung
- [Project Fluent](https://projectfluent.org/) (`fluent-templates`) mit Dateien
  `locales/{de,en}/main.ftl`, eingebettet ins Binary.
- Askama-Templates erhalten über das View-Modell ein `Lang`-Objekt mit
  Übersetzungsfunktion; Sprache aus Nutzerprofil, sonst `Accept-Language`,
  sonst Deutsch.
- Zahlen- und Datumsformat für die zwei unterstützten Sprachen im Modul
  `i18n::format` ohne zusätzliche Bibliothek.

## Alternativen
- *rust-i18n* (YAML, Makros): ohne CLDR-Pluralregeln.
- *gettext*: erfordert Extraktions- und Kompilierwerkzeuge (`xgettext`, `msgfmt`).
- *ICU4X für Zahlen und Datum*: alle Locales mit CLDR-Daten, zusätzliche
  Abhängigkeit und Binärgröße für zwei Sprachen.

## Konsequenzen
- Eine weitere Sprache erfordert eine `.ftl`-Datei und die Ergänzung von
  `i18n::format`; ab drei Sprachen ICU4X neu bewerten.
